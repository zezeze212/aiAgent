# Foreign key constraint 排查指南

## 典型报错

`Cannot delete or update a parent row: a foreign key constraint fails`

`Cannot add or update a child row: a foreign key constraint fails`

这个错误表示当前操作违反了外键约束。常见场景包括删除父表数据时子表仍有引用，或者插入子表数据时父表记录不存在。

## 常见原因

1. 删除父表记录前，没有先处理子表关联数据。
2. 插入或更新子表记录时，引用的父表主键不存在。
3. 表之间存在外键约束，但业务代码没有按依赖顺序操作。
4. 测试数据不完整，只插入了子表，没有插入父表。
5. 逻辑删除和物理外键混用，导致业务以为已删除，但数据库约束仍然存在。
6. 批量导入数据时父子表导入顺序错误。

## 排查顺序

1. 先从报错信息中识别约束名、父表、子表和关联字段。
2. 如果是删除或更新父表，先查询子表是否仍有引用记录。
3. 如果是插入或更新子表，先确认引用的父表记录是否存在。
4. 检查业务操作顺序是否符合外键依赖。
5. 检查测试数据、初始化脚本和导入顺序。
6. 如果业务允许删除父表，应明确处理子表数据策略，例如禁止删除、先删子表、逻辑删除或级联规则。

## 回答要求

1. 必须基于工具证据说明是哪张表、哪个字段或哪个约束存在问题。
2. 不要直接建议关闭外键检查。
3. 不要直接生成删除子表数据的 SQL，除非用户明确确认数据可以删除。
4. 建议优先检查父子表数据是否完整、操作顺序是否正确、约束设计是否符合业务。
5. 如果工具证据不足，应提示补充完整报错、表结构和相关数据样例。
