# Duplicate entry 排查指南

## 典型报错

`Duplicate entry 'xxx' for key 'uk_xxx'`

这个错误表示插入或更新数据时违反了唯一约束，目标唯一键上已经存在相同值。

## 常见原因

1. 插入了已经存在的唯一字段值，例如用户名、编码、订单号、业务流水号。
2. 接口重复提交，没有做幂等控制。
3. 新增和更新逻辑混用，本该更新的数据走了插入。
4. 唯一键设计包含多个字段，但代码只关注了其中一个字段。
5. 批量导入数据中存在重复记录。
6. 业务删除是逻辑删除，但唯一键没有包含删除标记，导致历史数据仍然占用唯一值。

## 排查顺序

1. 先从报错信息中提取重复值和唯一键名称。
2. 查询唯一键对应哪些字段，确认冲突条件。
3. 根据重复值查询数据库中已有记录。
4. 判断当前请求应该新增、更新、忽略还是提示重复。
5. 检查是否存在重复请求、前端重复点击、消息重复消费或任务重复执行。
6. 如果涉及逻辑删除，检查唯一键设计是否符合业务预期。

## 回答要求

1. 如果工具证据包含唯一键名称和重复值，应优先引用这些证据。
2. 不要直接建议删除旧数据，除非用户明确说明旧数据可以删除。
3. 不要直接生成 `UPDATE` 或 `DELETE`。
4. 建议优先检查唯一键字段、已有数据、接口幂等和新增/更新逻辑。
5. 如果无法确认唯一键字段，应提示用户补充表结构或唯一索引信息。
