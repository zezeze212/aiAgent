# Table doesn't exist 排查指南

## 典型报错

`Table 'database.table_name' doesn't exist`

这个错误表示 SQL 执行时访问的表在当前数据库连接环境中不存在。

## 常见原因

1. 表名写错，例如单复数、下划线、前缀或后缀不一致。
2. Mapper XML、注解 SQL 或动态 SQL 中引用了旧表名。
3. 当前连接的数据库不是预期数据库。
4. 本地、测试、生产环境的数据库结构不一致。
5. 建表脚本或迁移脚本没有执行。
6. MySQL 在部分系统中受大小写规则影响，表名大小写不一致会导致找不到表。

## 排查顺序

1. 先确认工具或日志中提取到的真实表名。
2. 确认当前应用连接的数据库地址、库名和账号。
3. 查询当前库中是否存在目标表。
4. 如果表不存在，检查建表脚本、迁移记录和环境初始化步骤。
5. 如果相似表存在，检查 Mapper XML、实体类 `@TableName` 和 SQL 拼接逻辑。
6. 如果只在某个环境报错，重点比较不同环境的库名、表名和迁移版本。

## 回答要求

1. 必须区分“表确实不存在”和“可能连接错环境”。
2. 如果工具证据已经确认当前库不存在该表，应直接说明当前连接环境下找不到目标表。
3. 不要虚构表结构，也不要假设正确表名。
4. 不要直接生成建表 DDL，除非用户明确提供表结构设计。
5. 建议优先检查数据库连接配置、Mapper 表名、迁移脚本和环境差异。
