# Data too long 排查指南

## 典型报错

`Data too long for column 'xxx' at row 1`

这个错误表示写入某个字段的值超过了数据库字段允许的长度或容量。

## 常见原因

1. 入参字符串长度超过字段定义长度，例如 `varchar(32)` 写入了更长内容。
2. 前端或接口没有做长度限制。
3. 字段原本只保存短文本，但业务开始写入长文本、JSON 或完整日志。
4. Java 字段类型和数据库字段类型不匹配。
5. 字符集差异导致实际占用长度超过预期。
6. 批量导入或第三方数据没有经过清洗。

## 排查顺序

1. 先从报错信息中提取超长字段名。
2. 以工具查询到的真实字段定义为准，确认字段类型和长度。
3. 检查本次写入的实际值长度和内容来源。
4. 判断是入参错误、字段设计不足，还是业务含义变化。
5. 检查前端限制、后端校验、DTO 注解和数据库字段定义是否一致。
6. 如果字段需要存长文本，再评估是否应该调整为更大的字符串类型或文本类型。

## 回答要求

1. 不要猜测字段长度，必须以工具查询到的表结构为准。
2. 如果工具没有返回字段定义，应提示补充表结构或使用表结构工具查询。
3. 不要直接生成修改字段长度的 DDL，除非用户明确给出目标长度和业务依据。
4. 建议优先检查入参长度、字段定义、前后端校验和业务字段设计。
5. 如果问题来自日志、JSON、富文本等长内容，应提示考虑字段类型是否适合。
